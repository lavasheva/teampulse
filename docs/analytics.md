# Расчёт вклада TeamPulse

Периоды выражаются в UTC. Начало включается, конец исключается. Неделя начинается в понедельник. Дата окончания проекта включается целиком. `asOf` при необходимости ограничивает период для текущего отчёта. Итоговый расчёт получает события за весь проект и применяет те же правила к накопленным баллам.

| Категория | Баллы до применения весов |
| --- | --- |
| Код | 1 балл за 20 допустимых изменённых строк (вставки + удаления), максимум 500 строк на коммит. Если есть только пути допустимых файлов, начальная оценка 0,25 балла за коммит. |
| PR | 1 за открытие, ещё 2 за слияние, 0 за закрытие без слияния. Вся жизнь принятого PR даёт 3 балла. Слияние в другой неделе даёт только прибавку. |
| Ревью | 1 за представленное ревью, 2 при наличии текста или запросе изменений. Dismissed и pending дают 0. |
| Issues | 0,5 за создание и 1 за закрытие, авторы действий берутся из событий. Текущее назначение задачи не доказывает, кто её выполнил. |

В PR учитывается работа по представлению и доведению изменений до принятия. Объём строк начисляется только по коммитам. Доставка одного события несколько раз не меняет результат. Дополнительная дедупликация использует GitHub URL объекта и вид действия. Для закрытий issues учитывается также UTC-дата: несколько закрытий задачи за день дают один сигнал закрытия.

Поле `work` хранит баллы до применения весов. Общий балл равен сумме произведений баллов категорий на веса, делённые на 100. Доля равна 100 × балл участника / балл команды. Доли категорий рассчитываются от суммы исходных баллов категории. При нулевом знаменателе доля равна нулю. События без сопоставленного участника остаются в отчёте отдельно и не входят в сумму баллов.

Активный день — день с действием, которое получило исходные баллы. Нулевой вес категории не отменяет активный день. Регулярность выражается долей активных календарных дней периода и средним интервалом в днях между активными датами. Для менее чем двух дат интервал отсутствует. Джини нормирован для конечной команды: для отсортированных баллов `x` это `Σ((2i−n−1)×xᵢ) / ((n−1)×Σxᵢ)`, где `i` начинается с 1. Если сумма равна нулю или участников меньше двух, Джини равен нулю.

## Примеры

1. 40 строк дают 2 балла кода. Вместе с открытым и принятым PR это 2 балла кода и 3 балла PR. При весах 50/20/20/10 общий балл равен 1,6.
2. При общих баллах 3, 1 и 0 доли составляют 75%, 25% и 0%, Джини равен 0,75.
3. В первую неделю команда получила 1 балл, целиком от А. Во вторую Б получил 9 баллов. Итоговая доля А составляет 10%.

## Корректировки кода

- Строки в lock-файлах, каталогах зависимостей и сборки, путях с признаками генерации и файлах с типичными бинарными расширениями исключаются. Чистое переименование определяется по статусу `renamed` и нулевой статистике. Переименование с правками оценивается по изменённым строкам.
- После фильтра файлов учитывается максимум 500 строк в коммите. Исключённые по пути строки и превышение лимита указываются отдельно и суммируются без двойного учёта.
- Коммиты до 5 известных строк и предварительно оценённые коммиты группируются по участнику и UTC-дню. Окно в 10 минут отсчитывается от первого коммита в серии. Серия получает баллы за максимум 20 измеренных строк. Серия только из предварительных оценок получает 0,25 балла. При смешанных данных используются измеренные строки.
- При неполном списке файлов учитываются только допустимые строки из переданной статистики по файлам. При наличии только путей предварительный балл возможен при хотя бы одном допустимом пути. Без путей и статистики по файлам начисления нет. Неизвестное число исключённых строк обозначено `null`. Список `commitsWithIncompleteStats` помогает пояснить предварительные расчёты.

Для распознавания чисто пробельных правок нужен вычисленный сборщиком признак или количество строк после сравнения без пробелов. Уверенная классификация бинарных и сгенерированных файлов требует явных признаков. Связь merge/squash-коммита с PR потребует SHA результата и SHA исходных коммитов. По названиям и объёму такие связи не выводятся.

## Флаги

Все флаги содержат команду, при наличии участника — его ID, UTC-период, серьёзность, объяснение, значение, порог, единицу измерения и идентификаторы подтверждающих событий. Значения берутся из настроек проекта.

| Флаг | Условие |
| --- | --- |
| `inactivity` | У участника не меньше заданного числа полных дней без учитываемых действий, при этом у коллеги есть активность за это время. |
| `teamInactivity` | Столько же полных дней без учитываемых действий команды и событий с неизвестным автором. |
| `imbalance` | В команде от трёх участников доля одного участника строго выше порога. |
| `lateBurst` | Доля взвешенного вклада участника за три UTC-дня, включая день контрольной точки, строго выше порога. Знаменатель — его вклад от начала отчёта до этой точки. Требуется хотя бы один наблюдаемый день до трёхдневного окна. Точки — завершившиеся в периоде вехи и окончание проекта. Для завершённой недели без них используется воскресенье. |
| `excluded` | Известные исключённые строки участника, поделённые на измеренные строки, строго превышают порог. При неполной статистике это нижняя оценка. |
| `unknown` | В периоде есть хотя бы одно событие без сопоставленного участника. |

Для порогов неактивности, выходящих за пределы недели, бэкенд может передать `historyStartsOn` и события с этой даты. Это начало фактически покрытой истории. Предшествующие события влияют только на неактивность. Для незавершённого периода передавайте `asOf`. День, который ещё не закончился, не прибавляется к сроку тишины.

Пустой снимок за семь завершённых дней выдаёт флаг тишины команды. При подключении воркера считайте этот период наблюдаемым после загрузки истории репозитория за него. Для команды без репозитория или с неполной синхронизацией покажите статус источника данных.

Для демонстрации можно взять трёх участников. А получил 1,6 балла и 78,05% общего вклада, Б получил 0,45 балла, у В нет действий семь дней. В коммите А 90 строк из 130 относятся к lock-файлу. Движок вернёт перекос вклада для А, 69,23% исключённых строк для А и тишину участника В.

## Недельная сводка

`generateWeeklySummary(result, members, provider?)` собирает русский текст из рассчитанного недельного результата. В тексте есть виды работ, активность участников, лидирующие доли, отмеченные сигналы и повод для внимания руководителя. Модель выбирает, какой из подтверждённых результатов и сигналов выделить. Приложение проверяет выбранные индексы и формулирует текст локально. Провайдер получает только виды и количества действий, обезличенные показатели и численные условия флагов. Имена, ссылки, сообщения коммитов и содержимое файлов в запрос не входят.

Без провайдера, при пустой неделе, ошибке или неверном ответе возвращается детерминированный шаблон. Поля `source`, `provider` и `fallbackReason` позволяют показать происхождение сводки. `evidenceEventIds` связывает выбранный сигнал с событиями.

- `createYandexGptProvider({ apiKey, folderId, model? })` использует ключ сервисного аккаунта. [Документация Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-basic).
- `createGigaChatProvider({ authorizationKey, scope?, model? })` получает токен по OAuth. Для соединения при необходимости задайте доверенный корневой сертификат через `NODE_EXTRA_CA_CERTS`. [Авторизация GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).

У обоих адаптеров по умолчанию 10 секунд на запрос сводки. Ключи передаются из конфигурации серверного воркера. Проверки адаптеров используют моки HTTP.
