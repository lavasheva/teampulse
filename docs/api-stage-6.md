# Этап 6: участники и доступ

Ветка `backend/stage-6-access-management`. В режиме `VITE_DATA_SOURCE=api` на странице проекта появился раздел «Участники и доступ».

## Полномочия

Владелец организации назначает и снимает руководителей своего проекта. Указывается GitHub-логин пользователя, который уже хотя бы раз вошёл в TeamPulse. Выдаётся доступ только к выбранному проекту. Глобального поиска пользователей и выдачи личных email нет. Владелец организации сохраняет доступ независимо от списка руководителей.

Руководитель проекта и владелец могут менять роль существующего участника команды между `participant` и `observer`, удалять членство, создавать приглашения обеих ролей, просматривать активные приглашения и отзывать их. Обычный участник и наблюдатель этих полномочий не имеют. Наблюдатель видит только свою команду и не подключает репозиторий, не подтверждает авторство и не меняет настройки проекта.

Удаление членства закрывает доступ через эту команду, но сохраняет независимые права руководителя/владельца. В интерфейсе удаление подтверждается отдельной кнопкой. Само удаление не является блокировкой: действующая ссылка позволяет вступить снова, поэтому при необходимости нужно отозвать активные приглашения.

## Приглашения

`Invitation.role` хранится в БД и не принимается от пользователя при вступлении. Старые приглашения мигрируют в `participant`. При повторном вступлении в ту же команду существующая роль сохраняется: ссылка участника не повышает наблюдателя. Одновременно состоять в двух командах одного проекта нельзя.

Список приглашений содержит ID, роль и даты, но не токен/хеш. Открытая ссылка выдаётся только при создании. Отзыв запрещает новые вступления, не удаляя тех, кто уже вступил.

## API

Все маршруты требуют сессию, изменяющие запросы — Origin и CSRF.

| Метод | Путь после `/api` | Назначение |
| --- | --- | --- |
| GET | `/projects/:projectId/access` | Владельцы, руководители, активные приглашения и право назначать руководителей |
| POST | `/projects/:projectId/managers` | Только владелец; тело `{ githubLogin }` |
| DELETE | `/projects/:projectId/managers/:userId` | Только владелец; снять права руководителя |
| PUT | `/projects/:projectId/teams/:teamId/members/:userId` | Тело `{ role: "participant" или "observer" }` |
| DELETE | `/projects/:projectId/teams/:teamId/members/:userId` | Удалить членство |
| POST | `/projects/:projectId/invitations` | Необязательная роль; по умолчанию `participant` |
| DELETE | `/projects/:projectId/invitations/:invitationId` | Отозвать приглашение |

Сочетание project/team/user проверяется сервером; недоступные объекты возвращают 404. Изменения руководителей и участников сериализуются блокировкой проекта и проходят проверку полномочий внутри транзакции.

## История и аналитика

Удаление и смена роли не удаляют события GitHub. При изменении состава/ролей и новом вступлении создаются запросы пересчёта всех недель с событиями команды. Аналитический вход включает только текущих участников: наблюдатель или удалённый участник не получает `actorId` даже при сохранённом историческом сопоставлении автора. При повышении наблюдателя до участника запускается повторное сопоставление завершённого импорта.

## Проверки

Добавлены PostgreSQL-тесты владельца/руководителя/участника/наблюдателя/постороннего, CSRF, границ проекта и команды, запрета повышения через приглашение, отзыва, сохранения событий и пересчёта. Браузерный сценарий проверяет назначение и снятие руководителя, смену роли, создание/отзыв приглашения наблюдателя и удаление участника через интерфейс.

Запуск: `pnpm --filter @teampulse/api test:integration` и `pnpm test:e2e:api` с отдельной `TEST_DATABASE_URL`, оканчивающейся на `_test`. Перед запуском обновлённого API применить `pnpm --filter @teampulse/api db:deploy` и сгенерировать Prisma Client.
