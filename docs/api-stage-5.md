# Этап 5: реальные данные в клиенте

Ветка `backend/stage-5-api-integration` подключает клиент к API. Расчёт вклада, флаги, недельные сводки и их планировщик пока не реализованы: модуль Вари ещё отсутствует. Демо остаётся доступным отдельно.

## Запуск

Настрой API по `apps/api/README.md`, подними PostgreSQL/Redis и примени миграции командой `pnpm --filter @teampulse/api db:deploy`. Миграция этого этапа переводит прежние равные веса 1/1/1/1 в проценты 25/25/25/25, сохраняя соотношение.

Скопируй `apps/web/.env.example` в `apps/web/.env.local`, установи `VITE_DATA_SOURCE=api`. Запусти API и `pnpm dev`. Открывай `http://localhost:5173`; `WEB_ORIGIN` сервера и OAuth callback должны использовать тот же hostname. Vite перенаправляет `/api` на `http://127.0.0.1:3000`, сохраняя Origin для проверки CSRF. При публикации нужен аналогичный reverse proxy и настройки production cookie.

Для демо установи `VITE_DATA_SOURCE=demo` и перезапусти Vite. Выбор источника фиксируется во время сборки; по умолчанию используется демо.

## Возможности

- Настоящий OAuth, серверная сессия, CSRF и выход.
- Создание организации, проекта и команды; приглашение и выбор команды после входа.
- Подключение репозитория по `владелец/название`: installation ID сервер определяет самостоятельно и проверяет права пользователя.
- Состояние импорта, страницы событий и неизвестных авторов, подтверждение авторства и профиль участника с количеством событий.
- Настройки проекта: API проверяет даты, веса с суммой 100%, пороги и контрольные точки. Интерфейс редактирует название, даты и веса, сохраняя остальные настройки.
- Сервер фильтрует проекты, команды и участников по доступу. Рабочее пространство возвращает до 100 проектов.

`GET /api/workspace` выдаёт доступные организации, проекты, команды, настройки и возможности текущего пользователя. `PUT /api/projects/:projectId/settings` доступен руководителю/владельцу; изменение создаёт запросы пересчёта затронутых недель. `GET /api/teams/:teamId/members/:memberId` возвращает участника и сырые количества событий. Это не оценка вклада.

## Граница аналитики

`packages/shared/src/analytics.ts` — предложение контракта для согласования с Варей. Внутренний `AnalyticsInputService.week` собирает согласованный снимок событий и настроек за неделю UTC, учитывает даты проекта и переданную версию исходных данных. Секреты и GitHub tokens в контракт не входят.

Публичный API сообщает `analytics.status=not_configured`, интерфейс показывает «Вклад ещё не рассчитан». Сохранение результатов, расчёт долей, флагов, ИИ-сводок и запуск недельных заданий требуют реализации и согласования аналитического модуля. Запросы пересчёта из этапа 4 сохраняются, но аналитическим обработчиком пока не исполняются.

## Проверки

Обычные проверки: `pnpm lint`, `pnpm build`, `pnpm test`. Интеграционные тесты: `pnpm --filter @teampulse/api test:integration` с отдельной `TEST_DATABASE_URL`, имя БД должно оканчиваться на `_test`.

`pnpm test:e2e` проверяет демо. `pnpm test:e2e:api` проверяет в браузере реальные HTTP, сессии, приглашение, PostgreSQL, подписанное событие, claim и запрет доступа к чужой команде. Только внешние OAuth/GitHub заменены тестовыми провайдерами. Тестовый сервер запускается лишь с `NODE_ENV=test` и отдельной тестовой БД; реальные `.env` credentials не загружаются. Нужен установленный Playwright Chromium; локально можно выбрать установленный Chrome через `PLAYWRIGHT_CHANNEL=chrome`.

CI для PR в `develop`/`main` поднимает PostgreSQL/Redis, применяет миграции и запускает сборку, lint, unit/integration/smoke и оба браузерных набора на Node.js 24.
