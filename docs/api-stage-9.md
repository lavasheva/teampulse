# Этап 9: существующий интерфейс и реальные данные

Используются экраны и стили интерфейса из текущего репозитория. Отдельной более новой ветки фронтенда при подготовке этапа не было; пользователь подтвердил работу с версией из репозитория.

## Что объединено

Демо и режим API используют общий `WorkspaceFrame`: боковую навигацию, список проектов и профиль. Права на настройки определяются отдельно для текущего проекта. Пользователь может быть руководителем одного проекта и наблюдателем другого; глобальная демороль для API не используется.

В режиме API используются стили существующего экрана входа, карточек команд, таблиц участников и вкладок команды. Компоненты для собранных данных находятся рядом с соответствующими демокомпонентами; числовые поля аналитики из демо в API не копируются.

| Маршрут | Реальные данные и поведение |
| --- | --- |
| `/projects` | Проекты, организации, число команд/событий, создание проекта |
| `/projects/:id` | Обзор, карточки команд, число участников и собранных событий, приглашение и добавление команды |
| `/projects/:id/participants` | Участники доступных команд, роли; руководителю — управление доступом и приглашениями |
| `/projects/:id/settings` | Руководителю: название, даты, веса, пороги и контрольные точки; сохранение в API |
| `/projects/:id/teams/:teamId` | Подключение репозитория, состояние импорта, вкладки участников и событий, сопоставление авторов |
| `/projects/:id/teams/:teamId/members/:userId` | Профиль участника и фактическое число событий |
| `/projects/:id/summaries` | Явное ожидание аналитики, без синтетических сводок |
| `/projects/:id/teams/:teamId/report` | Явное ожидание аналитики, без фиктивного итогового отчёта |

Проценты вклада, равномерность, флаги, графики аналитики и ИИ-тексты не готовы до подключения модуля Вари. На этих местах отображается ожидание расчёта или прочерк, а не нулевые/демонстрационные оценки. Суммарное число событий в обзоре — за всю сохранённую историю, не за неделю.

## Доступ и совместимость

API по-прежнему фильтрует проекты и команды на сервере. Интерфейс не заменяет серверную проверку полномочий. Участник видит свою команду, не видит управление доступом и ссылку настроек; прямое открытие настроек показывает недоступность.

Демо сохраняет собственные данные и сценарии. `VITE_DATA_SOURCE=api` включает реальные данные; `demo` остаётся режимом по умолчанию. Для проверки локальной интеграции нужны API, PostgreSQL и настроенный OAuth согласно этапам 2–5.

## Проверки

Браузерный сценарий с настоящими HTTP/Prisma проверяет общую навигацию, сохранение порога и контрольной точки после перезагрузки, пустое состояние сводок, вкладки команды, запрет настроек и управления доступом участнику, ширину мобильного экрана. Сохраняются снимки обзора и мобильных участников с тестовыми данными. Демо проверяется отдельно; каталоги результатов Playwright разделены на `test-results/api` и `test-results/demo`.

Unit-тесты общей навигации отдельно проверяют смешанные права в разных проектах. Запуск: `pnpm lint`, `pnpm build`, `pnpm test`, `pnpm test:e2e:api`, `pnpm test:e2e`. Сквозной API-тест требует отдельную `TEST_DATABASE_URL`, заканчивающуюся на `_test`; внешние OAuth/GitHub заменяются тестовыми провайдерами.
