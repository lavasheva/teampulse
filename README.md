# TeamPulse

TeamPulse показывает активность команд в GitHub и помогает руководителям и участникам видеть вклад в командный проект. Сейчас в репозитории каркас веб-клиента. Экраны MVP будут работать на локальных заглушках.

## Локальный запуск

Нужны Node.js 24 и pnpm 10.17.1. При использовании nvm запусти `nvm use` в корне проекта.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Vite напечатает адрес, обычно это `http://localhost:5173`. Проверки из корня проекта: `pnpm lint` и `pnpm build`.

Клиент находится в `apps/web`. В этой же структуре предусмотрены `apps/api` для сервера, `packages/shared` для общего контракта и `packages/analytics` для расчётов.

## План фронтенда

| Недели | Задачи | Что можно показать |
| --- | --- | --- |
| 1–2 | Каркас и навигация. Общие компоненты shadcn/ui и оформление по Figma. Черновой контракт с Сашей и Варей. Демо-вход, приглашение с выбором команды, «Мои проекты» и создание проекта. | Руководитель может создать демо-проект, участник может вступить в команду по демо-ссылке. |
| 3–4 | Подключение репозитория с состояниями выбора, загрузки истории, завершения и ошибки. Страница команды с долями вклада, недельной активностью, лентой событий, флагами и подтверждением неопознанных коммитов. | На странице команды видно событие из демо-репозитория. Когда появится API, общая контрольная точка команды — увидеть событие из собственного репозитория TeamPulse на этом экране. |
| 5–6 | Обзор проекта с индикаторами здоровья и проблемными командами сверху. Карточка участника с ключевыми работами и причинами исключения изменений. Экран «Сводки» с историей по неделям. | Руководитель находит команду с флагом, открывает объяснение и смотрит данные участника. Участник видит те же данные о своей команде. |
| 7–8 | Настройки проекта с датами, контрольными точками, весами, порогами и приглашением. Итоговый отчёт за весь период и стили печати. Сквозная проверка в Playwright и сверка с макетом. | Можно пройти сценарий от входа до отчёта и сохранить отчёт в PDF через печать браузера. |

Состояния загрузки, отсутствия данных и ошибки проверяем вместе с каждым экраном. Тесты Vitest и Testing Library добавляем с карточками и графиками. Контрольные точки на графиках входят в дополнительный объём.

### Заглушки и общий контракт

Экраны будут читать данные через TanStack Query. Запросы и действия сначала реализуем в одном типизированном слое заглушек с синтетическими данными. Там же смоделируем видимость данных для руководителя и участника. С Сашей и Варей сначала согласуем проект, команду, участника и событие, затем снимки метрик, флаги, сводки и статусы синхронизации. Согласованные типы попадут в `packages/shared`. При интеграции вызовы заглушек заменит REST-адаптер. Проверку прав выполняет API, а значения метрик и выводы флагов приходят из аналитики.

### Порядок коммитов

1. `chore(web): scaffold Vite workspace`
2. `feat(web): add routes and mock data access`
3. `feat(web): add sign-in and invitation flow`
4. `feat(web): add project list and creation`
5. `feat(web): add repository setup states`
6. `feat(web): add team dashboard`
7. `feat(web): add project overview and member details`
8. `feat(web): add weekly summaries and settings`
9. `feat(web): add printable team report`
10. `test(web): cover the demo flow`

Это порядок задач. Каждый крупный пункт можно разбить на несколько небольших коммитов с самостоятельным результатом. После появления GitHub-репозитория ведём задачи в ветках от `main` и проверяем через PR.
