# Этап 10: лента событий и журнал управления

Последняя доработка перед подключением аналитики: фильтры и порядок ленты, журнал действий руководителя и участников. Расчёт вкладов, флаги и ИИ-сводки остаются задачей модуля Вари.

## Лента

`GET /api/teams/:teamId/activity` требует сессию и доступ к команде. Руководитель видит команды своего проекта, участник/наблюдатель — свою команду.

Необязательные query-параметры:

- `kind`: `commit`, `pr_opened`, `pr_merged`, `pr_closed`, `review`, `issue_opened`, `issue_closed`.
- `author`: UUID пользователя либо `unmatched`. Выбор неизвестного UUID не открывает чужие данные: запрос всегда ограничен репозиторием текущей команды.
- `from`, `to`: календарные даты `YYYY-MM-DD`, обе включительно по UTC. Верхняя граница реализована как начало следующего дня, исключая его. Интервал с началом позже конца отклоняется.
- `cursor`: непрозрачный указатель следующей страницы.

Ответ совместим по форме с `CollectedEventsResponse`: `events` и `nextCursor`. На странице до 50 событий. Порядок — `occurredAt DESC, id DESC`; одинаковые даты не создают дублей при переходе по страницам. Курсор связан с командой и нормализованными фильтрами, поэтому при их изменении надо начать с первой страницы. Курсор проверяется, но не является секретом или правом доступа.

Лента обновляется, а не фиксируется снимком на всё время просмотра. Новые импорты и сопоставления авторов могут менять набор результатов; для актуального начала страницы можно обновить ленту или сбросить фильтры. Дополнительный индекс включает repositoryId, occurredAt и id.

Старый `GET /api/teams/:teamId/events` с UUID-курсором сохранён для совместимости. Клиент переключён на `/activity`; менять старые курсоры на новые между этими маршрутами нельзя.

В интерфейсе фильтры сохраняются в URL и переживают reload; сброс начинает новую выборку. Типы событий и числа в профиле участника подписаны по-русски. Неопознанные авторы по-прежнему сопоставляются отдельным действием; изменение авторства отражается при обновлении фильтра.

## Журнал

`GET /api/projects/:projectId/audit?cursor=...` доступен только владельцу организации и руководителям этого проекта. Участник, наблюдатель или руководитель другого проекта получают 404. UI показывает раздел «Журнал действий» только при соответствующих правах.

Записываются успешные пользовательские действия:

- назначение и снятие руководителей;
- смена роли, удаление участника и вступление в команду;
- создание и отзыв приглашения;
- подключение, переподключение и ручное отключение репозитория;
- сохранение настроек;
- подтверждение авторства.

Запись создаётся в той же PostgreSQL-транзакции, что и изменение. При откате нет ложной записи об успехе; при отказе записи аудита изменение также откатывается. Повторное назначение существующего руководителя, сохранение той же роли, повторное вступление в ту же команду, повторное подтверждение того же автора и повторное отключение уже отключённого репозитория не создают вторую запись. Повторное сохранение настроек или проверенное переподключение — самостоятельное выполненное действие и записывается.

Поля: ID/дата, тип действия, GitHub-логин исполнителя, команда, идентификатор объекта, публичное название/логин объекта, прежняя/новая роль при наличии. Снимок логина исполнителя сохраняется при удалении пользователя; FK actorId становится null. Email, токены приглашений, их хеши, сессии, ключи GitHub и полные тела запросов в журнал не копируются. Клиент получает только разрешённые поля.

Журнал начинается с применения миграции. Старые действия не восстанавливаются задним числом. Изменения истории GitHub и автоматические уведомления об отзыве App не являются пользовательскими действиями этого журнала: их текущее состояние отображается в статусе репозитория. Это журнал приложения, а не защищённое от администратора БД хранилище: прямые изменения SQL не покрываются и не предотвращаются.

Страницы журнала: до 50 записей, `createdAt DESC, id DESC`. Курсор связан с проектом. API изменения/удаления записей журнала отсутствует; удаление самого проекта каскадно удаляет его журнал. В текущем интерфейсе удаления проекта нет.

## Проверки и запуск

Новая миграция добавляет ProjectAudit, enum действий и индекс ленты. Перед локальным запуском обновить Prisma Client и применить `pnpm --filter @teampulse/api db:deploy`.

PostgreSQL-тесты покрывают 55 событий с совпадающими датами, фильтры по типу/автору/периоду, границы суток, некорректные запросы и курсоры, доступы, пагинацию журнала, отсутствие секретов и откат при ошибке аудита. Сквозной браузерный тест проходит фильтрацию/reload/сброс, подтверждение автора, просмотр журнала, запрет журнала участнику и мобильный экран. Демо проверяется отдельно.

Команды: `pnpm lint`, `pnpm build`, `pnpm test`, `pnpm --filter @teampulse/api test:integration`, `pnpm test:e2e:api`, `pnpm test:e2e`. Интеграционные и API-browser тесты требуют отдельной `TEST_DATABASE_URL`, заканчивающейся на `_test`.
