# TeamPulse

Бэкенд: [инструкция запуска API](apps/api/README.md), [распределение ответственности и поэтапный план](docs/backend-plan.md), [контракт входа и рабочего пространства](docs/api-stage-2.md), [события GitHub](docs/api-stage-3.md), [история и авторы](docs/api-stage-4.md). Реализованы NestJS/Prisma/PostgreSQL, серверные OAuth и роли, проекты/команды/приглашения, GitHub App, вебхуки, BullMQ, история и сопоставление авторов.

TeamPulse показывает активность команд в GitHub и помогает руководителям и участникам видеть вклад в командный проект. По умолчанию веб-клиент использует демо. В [режиме настоящего API](docs/api-stage-5.md) вход, проекты, команды и события доступны из PostgreSQL. Модуль аналитики готов к подключению. [План интеграции и приёмки](docs/analytics-handoff.md) и [формулы расчёта](docs/analytics.md).

[Управление участниками и доступом](docs/api-stage-6.md): руководители проекта, наблюдатели, удаление членства и отзыв приглашений доступны в режиме API.

[Управление репозиторием](docs/api-stage-7.md): отключение с сохранением истории, повторное подключение и сообщения об ошибках GitHub.

[Подготовка размещения и резервных копий](docs/api-stage-8.md): production-контейнеры, прокси и миграции; `pnpm test:deploy` проверяет отдельный стенд и настоящее восстановление PostgreSQL. Публичный сервер пока не настроен.

[Интеграция интерфейса](docs/api-stage-9.md): общая навигация демо/API, реальные участники и команды, отдельные настройки с порогами и контрольными точками. Для сводок и итогового отчёта предстоит подключить расчёты к API и экранам.

[Лента и журнал управления](docs/api-stage-10.md): фильтры событий и порядок по времени; руководителю доступен журнал изменений ролей, приглашений, настроек и подключения репозитория.

## Локальный запуск

Нужны Node.js 24 и pnpm 10.17.1. При использовании nvm запусти `nvm use` в корне проекта.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Vite напечатает адрес, обычно это `http://localhost:5173`.

## Демо

- Кнопка «Войти через GitHub» на главной открывает профиль преподавателя. В нём доступны список проектов, создание проекта с первой командой, обзор, сводки и настройки.
- «Перейти по ссылке» на экране входа открывает приглашение в демо-проект. Через приглашение можно войти как студент и выбрать команду. Участник видит только свою команду и может подтвердить авторство неопознанного коммита.
- В «Кодзилле» есть данные для графика, лента событий, флаги и итоговый отчёт. Кнопка «Сохранить как PDF» открывает печать браузера.
- Роль, созданные проекты и настройки сохраняются в хранилище сайта в текущем браузере. Приглашение в созданный демо-проект открывай в том же профиле браузера. Для сброса демо очисти данные сайта.

Вход, события, сводки и рассылка моделируются в браузере. Подключение репозитория отложено. В примере «Кодзиллы» уже есть репозиторий и синтетические события. Изменение весов, порогов и подтверждение автора сохраняются в демо, расчёт вкладов остаётся частью будущей интеграции с аналитикой.

## Проверки

```sh
pnpm lint
pnpm build
pnpm test
pnpm --filter @teampulse/web exec playwright install chromium
pnpm test:e2e
```

Клиент находится в `apps/web`. Общие черновые типы для интеграции находятся в `packages/shared`. Запросы идут через TanStack Query, данные выдаёт локальный адаптер из `apps/web/src/data`.
