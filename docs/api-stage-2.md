# API этапа 2: вход и рабочее пространство

Все пути начинаются с `/api`. DTO для клиента: `packages/shared/src/api.ts` (экспортируются через `@teampulse/shared`). Существующие демомодели клиента не заменяются серверными автоматически.

## Реальный вход через GitHub

Создай GitHub OAuth App в Settings → Developer settings → OAuth Apps. Для локальной разработки:

- Homepage URL: `http://localhost:5173`.
- Authorization callback URL: `http://localhost:3000/api/auth/github/callback`.
- В `apps/api/.env` заполни `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_CALLBACK_URL`.
- Секрет хранится только локально/в окружении сервера, не в Git и не в переменных `VITE_*`.

Регистрация OAuth App и разрешение пользователя — отдельны от авторизации Git для push. В дальнейшем установку GitHub App для чтения репозитория реализует этап 3.

Перейди браузером на `GET /api/auth/github`. Сервер создаёт попытку на 10 минут, задаёт HttpOnly-cookie `tp_oauth`, перенаправляет на GitHub. Используются state, привязка к браузеру и PKCE S256. Callback атомарно потребляет state, получает профиль и только подтверждённые email, создаёт/обновляет пользователя и выдаёт новую сессию на 7 дней. Старый предъявленный session token отзывается. Повторный callback отклоняется. GitHub access token не сохраняется и не возвращается клиенту.

Callback возвращает браузер на фиксированный `WEB_ORIGIN`, произвольного return URL нет. Отказ пользователя/неверный state дают 401, недоступный GitHub — 503. Если OAuth не настроен, старт входа возвращает 503; health endpoints остаются доступны.

## Сессия и CSRF

`GET /auth/me` → `{ user, csrfToken }`. Передавай cookie через `credentials: 'include'`.

Для POST/DELETE передавай `X-CSRF-Token` из `/auth/me`; сервер также проверяет точный `Origin` из `WEB_ORIGIN`. В браузере Origin выставляется автоматически. `POST /auth/logout` возвращает 204, удаляет сессию в БД и cookie.

Cookie: HttpOnly, SameSite=Lax, Path=/api, без Domain; Secure при `NODE_ENV=production`. В production нужны HTTPS для фронтенда и callback. Все ответы запрещены к кешированию. Ограничение запросов пока в памяти одного процесса: 120/мин на маршрут/IP, вход — 10/мин, callback — 20/мин. При нескольких экземплярах потребуется общий storage лимитов.

## Эндпоинты

Все ниже требуют сессию. UUID в путях валидируется; незнакомые поля тела и роль от клиента отклоняются с 400.

| Метод и путь | Назначение и доступ |
| --- | --- |
| `GET /organizations` | Организации, в которых пользователь владелец/руководитель; собственная роль в memberships |
| `POST /organizations` | `{ name, kind: university/school/company }`; создатель становится владельцем |
| `POST /organizations/:id/projects` | `{ name, startsOn, endsOn, teamName }`; только член организации, создатель руководит новым проектом |
| `GET /projects` | Только доступные проекты; участнику/наблюдателю возвращается только его команда |
| `GET /teams/:id` | Владелец организации, руководитель этого проекта или участник/наблюдатель этой команды |
| `POST /projects/:id/teams` | `{ name }`; владелец организации или руководитель этого проекта |
| `POST /projects/:id/invitations` | Те же права; возвращает `{ id, token, expiresAt }`, срок 7 дней; в БД только хеш |
| `DELETE /projects/:id/invitations/:invitationId` | Отзыв приглашения руководителем, 204 |
| `GET /invitations/:token` | После входа: название проекта/организации и список команд с числом участников |
| `POST /invitations/:token/accept` | `{ teamId }`; вступление только как участник, команда должна принадлежать приглашённому проекту |

`startsOn`/`endsOn` — валидные даты `YYYY-MM-DD`, окончание не раньше начала. Имена обрезаются по краям, от 1 до 120 символов. У руководителя организации нет автоматического доступа ко всем её проектам: доступ задаётся ProjectManager. Владелец организации видит все её проекты.

Повторное вступление в ту же команду идемпотентно. Вступление во вторую команду того же проекта — 409, в том числе при гонке запросов. Ограничение реализовано уникальным индексом БД и составным FK, не только проверкой сервиса. Истёкшее/отозванное приглашение — 404. Чужая команда/проект — 404, без раскрытия существования ресурса. Неавторизованный запрос — 401; неправильные Origin/CSRF — 403.

Мутации настроек проекта, назначение новых руководителей/наблюдателей, уход из команды и аналитические данные в этот набор эндпоинтов пока не входят. Создать наблюдателя или назначить другого руководителя через API пока нельзя; чтение и ограничения их существующих членств покрыты тестами. Вступление по приглашению не повышает существующую роль наблюдателя.

## Проверки с PostgreSQL

Обычные модульные и HTTP-тесты: `pnpm --filter @teampulse/api test`.

Для интеграционных тестов создай отдельную пустую БД `teampulse_test` и передай её URL:

```powershell
docker compose exec -T postgres psql -U teampulse -d postgres -c 'CREATE DATABASE teampulse_test;'
$env:TEST_DATABASE_URL='postgresql://teampulse:teampulse@localhost:5432/teampulse_test?schema=public'
pnpm --filter @teampulse/api db:generate
pnpm --filter @teampulse/api test:integration
```

Runner отказывается работать без имени БД с суффиксом `_test`, применяет миграции и запускает тесты. PostgreSQL, сессии, проверки доступа и HTTP настоящие; только GitHub profile exchange подменён. Тесты удаляют только собственные фикстуры. Полный вход с настоящим GitHub требует ручной проверки с зарегистрированным OAuth App.

Миграция переносит projectId из Team в существующие TeamMembership. Если в прежних данных человек уже состоит в нескольких командах одного проекта, уникальный индекс не создастся: сначала нужно осознанно разрешить эти конфликты, данные миграция не удаляет.

Протокол проверен по [официальной документации GitHub OAuth](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps).

Проверено 18.11.2026 на Node.js 24.22.3: lint и сборка всего монорепозитория; 23 теста API, 2 теста клиента, 11 интеграционных тестов на PostgreSQL и smoke с настоящей БД. Обе миграции применены к чистой тестовой БД; миграция этапа 2 также применена поверх этапа 1 в локальной БД разработки. Prisma diff не нашёл расхождений. Вход с настоящим GitHub пока не проверен.
